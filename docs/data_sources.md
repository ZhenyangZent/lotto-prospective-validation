# 資料來源與規則紀錄

存取日期：2026-07-28（Asia/Taipei）

## 官方來源

1. [台灣彩券－大樂透遊戲介紹](https://www.taiwanlottery.com/lotto/info/lotto649/)
   - 號碼範圍 01–49，每注選 6 個不重複號碼。
   - 每注售價新臺幣 50 元。
   - 每期開出 6 個一般獎號，再從其餘 43 個號碼開出 1 個特別號；特別號只用於貳、肆、陸、柒獎。
   - 官方規則素材另明示單注頭獎理論機率為 1/13,983,816，未滿 18 歲不得購買或兌領彩券。

2. [台灣彩券－各期開獎結果資料下載](https://www.taiwanlottery.com/lotto/history/result_download/)
   - 官方年度 ZIP 的入口。本系統呼叫同頁使用的官方 API：
     `https://api.taiwanlottery.com/TLCAPIWeB/Lottery/ResultDownload?year=YYYY`。
   - API 回傳台灣彩券 CDN 上的年度 ZIP，不使用第三方鏡像。
   - 官方欄位說明：遊戲名稱、期別、開獎日期、銷售總額、銷售注數、總獎金、獎號 1–6、特別號。
   - 官方頁面標示每月 5 日更新至前一個月。當年度資料因此可能不是截至今日的即時全集。
   - 可下載民國 96 年起（西元 2007 年起）的第三、四、五屆公益彩券資料。

3. [中信銀行彩券管理部－獎號與獎金分配](https://lotto.ctbcbank.com/result_all.htm)
   - 當期官方結果列出以下條件：頭獎 6 個、貳獎 5 個加特別號、參獎 5 個、肆獎 4 個加特別號、伍獎 4 個、陸獎 3 個加特別號、柒獎 2 個加特別號、普獎 3 個。
   - 頭獎至肆獎為浮動獎金，由該獎項所有中獎注數均分；當期無人中獎時累入次期該獎項。
   - 伍獎、陸獎、柒獎、普獎為固定每注 2,000、1,000、400、400 元。促銷、加碼、保證獎金與屆次結束時可能另有公告，不能由歷史一般規則推定。

4. [中信銀行公告－大樂透伍獎固定 2,000 元及獎金規則變更](https://lotto.ctbcbank.com/news1060706.htm)
   - 說明總獎金支出率及頭獎至肆獎為扣除固定獎後再依比例、實際中獎注數分配的制度背景。

## 中獎條件

| 獎項 | 一般獎號命中 | 特別號 | 類型 |
|---|---:|:---:|---|
| 頭獎 | 6 | 不適用 | 浮動／可累積 |
| 貳獎 | 5 | 是 | 浮動／可累積 |
| 參獎 | 5 | 否 | 浮動／可累積 |
| 肆獎 | 4 | 是 | 浮動／可累積 |
| 伍獎 | 4 | 否 | 固定 2,000 元 |
| 陸獎 | 3 | 是 | 固定 1,000 元 |
| 柒獎 | 2 | 是 | 固定 400 元 |
| 普獎 | 3 | 否 | 固定 400 元 |

獎金規則可能變更；涉及實際投注或兌獎時必須再次查看當期官方公告。本專案只將獎項條件用於理論機率，不估計投資報酬。

## 原始資料保存與欄位

- `data/raw/YYYY.zip`：官方原始年度檔，不修改。
- `data/raw/manifest.json`：下載日期、API、CDN URL 及錯誤紀錄。
- `data/processed/lotto649.csv`：只保留遊戲名稱恰為「大樂透」的記錄；六個一般號碼排序後存放。
- 正規欄位：`draw_id`, `draw_date`, `number_1`…`number_6`, `special_number`, `sales_amount`, `sales_count`, `total_prize`, `jackpot`, `winner_count_by_tier`, `prize_by_tier`, `source`, `source_version`。官方「總獎金」存入 `total_prize`；它不是頭獎金額，故官方未提供單獨頭獎金額時 `jackpot` 保持空值。
- 官方年度主檔沒有各獎項中獎注數與單注獎金時，系統保留空 JSON，不從其他來源補造。

## 無法自動下載時

1. 從上述官方下載頁手動取得年度 ZIP，放入 `data/raw/` 後執行 `python -m src.main download`；或解壓並取得大樂透 CSV。
2. CSV／Excel 欄位至少需包含期別、開獎日期、獎號 1–6、特別號。
3. 執行 `python -m src.main download --manual 路徑`；若是整理後檔案，應自行確認 `source` 說明真實，不得把第三方資料冒充官方。
4. 再執行 `validate`。任何錯誤會寫入 `reports/validation.json` 並中止後續嚴格分析。
